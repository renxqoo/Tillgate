# ADR-0009：接口权限绑定数据化——全局 ACL 中间件取代逐端点 guard 声明

- 状态：已接受（2026-08-24）
- 关联：ADR-0008（动态角色 + 权限树）、docs/admin-rbac-dynamic/
- 反转对象：ADR-0008 的「方案 B 逐端点 guard(code) 声明」（执行面留代码）

## 背景

ADR-0008 把执行面钉在代码（`guard('users:read')` 贴在路由上）、注册面放 DB——
双事实源。该形态下「资源节点全字段编辑 + 全节点删除」会产生系统性漂移：
改码 → 守卫仍查旧字符串，角色绑不到新码 → 非超管全体静默失权（用户裁决明确要求
放开全字段 CRUD,且质疑双源架构本身）。

## 决策

**执行面数据化**：接口 → 权限绑定入 DB（`endpoint_permissions`,迁移 0084），
一个全局 ACL 中间件取代全部逐端点声明：

- 绑定按 **permission_id 外键**（不按码字符串）——改码零漂移（改名后绑定/授权/
  判定三方自动一致,e2e §L 实证）；
- 未绑定路由 **fail-closed 403** `endpoint_unbound`（公开/自身白名单代码侧:
  探针/登录族/me 族/logout;非 /v1 路径放行保留 404 语义）;
- **超管 isSuper 短路**（含未绑定端点）——误删绑定的兜底恢复路径:超管始终可进
  后台补配;
- 每请求一次绑定表 + 权限树查询（~百行小表,管理面 QPS 无感;缓存挂账）;
- 种子 = 原 104 处 guard 声明机械导出 + 绑定管理端点自身 4 条。

**完备性保证的替换**：TS 编译期强制（忘挂码不可编译）退场,换双保险——
运行时 fail-closed（新端点忘配绑定 = 除超管外全 403,开发期一眼可见）+
e2e 语义断言。pattern 手误只会导致「匹配不到 → 默认拒绝」,不构成放行漏洞。

**语义变更（有意）**:未注册 /v1 路径由 404（探测抗性）变为 401（无凭据）/
403 `endpoint_unbound`（非超管）/404（超管）——fail-closed 取代探测抗性,
两者都不泄漏路由清单。

**共享页码语义**（实施期发现）:页面共用域读码（用户页/限流页共用 users:read）
是合法形态——码唯一性仅约束按钮（与 DB 部分唯一索引同口径）;角色按码授权
授**全部**同名节点。

## 后果

- 26 个路由文件回归零中间件（比方案 B 更干净）;`guardFactory` 与
  `permission.ts` 退役,`acl.ts` 接棒;
- ADR-0008 的 enforced 注册表降级为种子清单（不再被运行时引用）;
  启动对账（enforced ⊆ DB 活动码）随执行面数据化失去意义,由绑定表本身取代;
- 接口绑定管理成为一等运营能力（/v1/endpoint-bindings CRUD + 权限资源页面板）;
  换绑/解绑下一请求生效（e2e §L 实证）;
- ADR-0008 记录的「方案 B 业界坐标」仍然成立——本 ADR 记录的是**前提变更**:
  当「接口归属」从架构事实变为运营事实,Shiro filter chain / Casbin / 网关 ACL
  一族（绑定即数据）才是正确形态。
