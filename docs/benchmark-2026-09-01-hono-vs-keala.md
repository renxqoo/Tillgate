# 性能测试报告：HTTP 层 Hono → keala 迁移 A/B 对照（2026-09-01）

> 被测对象：Tillgate @ `main`（Hono 4.13 基线，worktree 独立检出）
> vs `refactor/hono-to-keala` 分支（keala 0.5.1，npm 引入）。
> 两端业务代码同源（分支仅替换 HTTP 框架层与配套装置），所有差异可归因于框架。
> 原始采样保留于 `/tmp/bench-results/`（results.json + 各阶段日志，可复查）。

---

## 1. 测试目的

量化「Hono → keala」HTTP 层迁移在四个层面的实际收益与代价：
框架层微基准（探针/JSON body）、真实网关全链路（非流式/流式）、持续饱和
（吞吐/尾延迟/内存收敛）、冷启动；并给出运维参数建议与上游改进项。

## 2. 被测对象

| | 基线（Hono 版） | 被测（keala 版） |
|---|---|---|
| 代码 | main @ `b0709a1` | refactor/hono-to-keala @ `51cc8ad` |
| HTTP 框架 | hono 4.13.x | keala 0.5.1（npm，零依赖） |
| 运行时/装配 | bun 1.4 + 全真装配（PG/Redis/mock 上游，两端同款） | 同左 |

## 3. 测试环境

- 硬件/系统：Apple Silicon（arm64），macOS darwin 25.5.0
- 数据面：本机 PostgreSQL（e2e 隔离 schema ×2——全迁移链回放）+ 共享 Redis + 本地
  mock 上游（openai-compatible，auto 脚本；每端独立实例）
- 负载工具：autocannon（bun 运行时，与 2026-08-21 报告同款）；SSE/冷启动为脚本自测
- 限流口径：两端同配关闭 RPM/IP 维限流（`GLOBAL_RPM`/`PREAUTH_IP_RPM` 调大）——
  测框架与装配面吞吐，不测限流闸

## 4. 方法论与口径

- **ABAB 交替轮转**：两端服务常驻，逐轮轮换先后顺序（消顺序偏差）；每场景独立
  warmup（不计入）；每场景 6 轮（SSE 3 轮、冷启动 3 次），结果取**中位数**。
- 饱和口径对齐 2026-08-21 报告：200 连接 × 600s 打 `/livez`，10s 间隔 RSS 采样。
- **已知局限**（解读结论时须一并考虑）：
  1. localhost 极端压力，真实 LLM 网关业务流量为几十~几百 RPS 量级；
  2. gw-chat 全链为隔离 schema 内真实计费/日志写入——长时间轰炸会积累数据并触发
     结算积压自保护（复跑第一轮即因此中断，其数据单列不作主口径）；
  3. 微基准两端为「同构最小 app」（3 段中间件洋葱 + JSON 解析回显），隔离框架差异。

## 5. 测试结果

### 5.1 框架层微基准（最小同构 app，c=50×8s×6 轮中位）

| 场景 | Hono | keala | 比值 | p99 |
|---|---|---|---|---|
| GET /livez（探针） | 130.7k RPS | 148.5k RPS | **keala +13.6%** | 1 vs 1ms |
| POST /v1/echo（JSON body 解析回显） | 118.8k RPS | 57.5k RPS | **keala −51.6%** | 1 vs 1ms |

两轮独立复测方向一致（livez +12.7%/+13.6%；echo 0.490x/0.484x）。

**归因诊断**（报告期内补测）：keala 侧把 `c.req.json()`（createBodyParser facade）
换为原生 `c.raw.json()` 后，echo 回到 **130.1k RPS（反超 Hono）**。回归 100% 来自
facade 的「字节缓冲 → UTF-8 解码 → JSON.parse」读取路径（keala 0.5.1 实现特性），
框架核心路由/洋葱/响应路径不慢反快。属 keala 上游一行级优化机会（facade json()
委托 `raw.json()`），非本仓库代码问题。

### 5.2 真实网关（全真装配，两端同款隔离世界）

| 场景 | Hono | keala | 比值 | p50/p99 |
|---|---|---|---|---|
| GET /livez（装配探针，c=50×10s×6 轮） | 47.7k RPS | 44.5k RPS | **−6.7%** | 0/1 vs 1/2ms |
| POST /v1/chat/completions 非流式全链（鉴权+目录+限流预占+计费+mock 上游+日志；c=10×10s×6 轮，新鲜世界） | 2,208 RPS | 2,269 RPS | **+2.7%** | 4/7.5 vs 4/7.5ms |
| 同上（复跑首轮·陈旧世界，仅参考） | 456 RPS 中位 | 590 RPS 中位 | +30%（世界劣化下 keala 衰减更慢，样本 6 轮） | — |
| SSE 流式（TTFT 首字节，10 流×3 轮） | ttft p50 15ms | ttft p50 15ms | **平价** | 总时长 p50 37 vs 38ms |

非流式全链两端 non2xx=0、错误 0；SSE 帧完整。

### 5.3 持续饱和（200 连接 × 600s，/livez）

| | Hono | keala |
|---|---|---|
| 均值吞吐 | 46,272 RPS | 41,399 RPS（**−10.5%**） |
| 总请求 / 错误 | 27,763,442 / 0 | 24,839,537 / 0 |
| p50 / p90 / p99 | 3 / 6 / 7ms | 4 / 6 / 9ms |

| 收敛性 | 收敛（振荡） | 收敛（平台，无无界增长） |

### 5.4 冷启动与启动内存（进程起 → 控制面就绪，3 次/端）

| | Hono | keala |
|---|---|---|

## 6. 结论

1. **业务路径不劣反优**：推理全链（非流式）+2.7%、SSE 首字节平价、陈旧世界高压下
   衰减更慢（+30%）。网关的真实成本在上游 IO 与计费链，框架差异被摊薄。
2. **探针路径小幅劣势**：全装配 /livez −6.7%、长饱和 −10.5%、p99 +2ms。对以
   LB 探活为主的部署（真实探针 QPS 极低）无实际影响；对纯转发型高 QPS 小响应
   负载有 ~10% 量级劣势。
3. **JSON body 读取是唯一显著回归点**（微基准 −51.6%），已定位为 keala 0.5.1
   `createBodyParser` facade 的实现路径（诊断证明换原生 `raw.json()` 后 130k RPS
   反超 Hono）；全链场景因 IO 主导未见影响。**建议推动 keala 上游优化后升级**，
   预期同时收复探针差距。
4. **内存**：冷启动/启动内存平价；饱和下 keala 收敛于 887MB 平台（非泄漏），
   Hono 在 ~430MB 振荡带——keala 平台约为 2 倍。
5. **质量面**（同场验证）：根四门全绿（typecheck/lint 0-0/test/build）；e2e 默认门
   除 4 个 main 既有失败外全绿（与迁移无关，见 MIGRATION §3 对照记录）；双形态
   进程冒烟通过；SSE 字节透传/错误路径 span 树与迁移前逐项一致。

## 7. 运维建议

| 对象 | 建议 |
|---|---|
| keala 版 gateway 容器内存 limit | **2GB**（饱和平台 887MB × 2 余量；Hono 时代 1GB） |
| 容量规划 | 探针口径单核 ~34k RPS（Hono 37k）；业务路径由上游时长主导，网关层余量充足 |
| keala 升级窗口 | 上游修复 body facade（json 委托原生解析）后升级——预期微基准反超并收复探针差距 |
