# 工程纪律（Engineering Principles）

本仓库所有变更的验收依据。评审与自查时逐条对照；与既有习惯冲突时，以本文为准。

## 0. 不分版本、直接实现最终形态

不规划 v1/v2/v3 分期版本。每个特性一次实现到最优、全面、生产可用的形态；
范围之外的能力明确声明"不做"并单独立项，不留半成品占位代码。

## 1. 治本不治标（根因优先）

- 并发与竞态问题不用重试、延时、捕获忽略等补丁掩盖，而是把业务不变量
  下沉到数据库层（唯一索引/部分唯一索引、CHECK 约束、外键），
  让非法状态在结构上不可能发生；应用层只负责把约束冲突翻译成业务错误。
- 口径类问题（如展示、授权、结算数字不一致）不逐处修补展示，
  而是先统一为一个权威公式/实现，所有消费方引用同一处。

## 2. 删除优于兼容（单一真相）

- 废弃功能不是标记 deprecated 后永久共存，而是在一次变更中删干净：
  字段、分支、接口、配置、文档全链路移除。
- 不引入 if-old / if-new 双路径；代码库任何时刻只有一种行为真相。
  旧数据的收敛用一次性迁移完成，不用运行时分支维持。

## 3. TDD 红-绿-重构

- 行为类修复先写能复现 bug 的失败测试——红灯必须真实复现问题，
  不接受"理论上会失败"的推断；然后写最小实现使其通过；最后做
  不改行为的结构重构。
- 修复与重构不同步进行，保证每一步都可独立验证。

## 4. 组件化下沉

- 跨模块/跨包重复的逻辑抽取为共享组件，放到被多方依赖的基础层；
  包内重复出现的模式抽取为内部收口函数，统一入口、统一语义、统一错误处理。
- 判断标准：同一段逻辑第三次出现就必须抽取；复制粘贴是缺陷的温床。
- 避免过度封装。

## 5. 破坏性变更一次做完整

- schema 迁移、后端、前端、类型定义、测试、种子数据、文档必须在
  同一次变更中同步完成；不允许"后端已改、前端未动、测试未适配"的
  半迁移状态合入主干。
- 加约束前先校验存量数据满足新约束（如加唯一索引前查重复数据），
  不满足先治理数据再上约束。

## 6. 错误语义分级

- 客户端输入错误 → 400 / 404 / 409；
- 业务规则拒绝 → 明确的业务错误码与可读信息；
- 只有真正的服务端故障才返回 500。
- 任何可预期的拒绝都不允许伪装成异常或崩溃；约束冲突、校验失败
  必须在边界层完成翻译，绝不裸泄漏底层错误码。

## 7. 测试数据纪律

- 需要留档复查的验证数据用统一前缀标识并保留；
- 测试清理只删除自己创建的数据，并通过前缀等双重条件防止误删
  业务或共享数据；
- 生产代码禁止绕过状态机直接改库；测试代码作为例外也必须同步
  清理其衍生投影数据。

## 8. 回归即验收

- 每项修复的"完成"定义是全量回归通过：全部测试套件 + 类型检查
  + lint + 关键端到端链路，四关全绿才算完成（`pnpm regress`）；
- 改动波及公共基建（测试 helper、共享类型、构建产物）时，必须证明
  既有失败用例恢复正常，而不是绕过、跳过或删除它们。
