# 三件文档模板与产出物细则

> 复杂度决定文档数量：小功能可合一；跨包/跨应用重构必须三件分离。文档之间相对链接
> 互引，同一决策只在一处定义、他处引用。

## DESIGN（设计基线）

定稿后少改；实现推翻设计时，同一提交内先改本文。

### 必含三块

1. **外部契约**
   - API 形态：参数平铺不嵌套、结果判别联合、可选参数全部有缺省；
   - 事件时序契约：终态保证最后、一次性事件恰好一次、事件词表封闭；
   - 消费方是谁、怎么消费（明确到调用形态）。
2. **内部问题域**
   - 处理什么：逐动词列出；
   - **明确不处理什么**：每项写清归属哪个消费方，不留白。「不处理」不写清楚，
     未来一定会变成隐藏职责。
3. **并发与性能预算**
   - 数字化硬约束：每帧同步耗时量级、每连接内存上界、全局定时器个数、
     回调内禁 IO、热路径禁止的动作清单；
   - 预算违反 = 缺陷，不是优化建议。
4. 裁决落档：设计讨论中的每个方向性裁决（错误归一方式、机制/策略分离点、
   数据面与观察面边界）标注「用户裁决」。

## IMPLEMENTATION（施工图）

1. **旧实现审计结论**（引用审计清单编号，不重复抄写）；
2. **逐模块裁决表**：| 旧文件 | 裁决 | 审计状态 | 动作 |；
3. **拆分决策**：目标目录结构、共享件提取（引用重复编号）、契约演进（引用缺口），
   每条决策必须引用审计证据，禁止凭感觉；
4. **测试计划**（见主文档 §5）；
5. **实施顺序**：阶段划分、每阶段验收点。

## 7. 验收（全部满足才算完成）：四门、覆盖率数字、行为对照清单逐项、

## 8+ 实施记录：每波收口追加一节——交付物、门禁数字、新增裁决补录、

实施期发现并修复的真实缺陷（编号+症状+修法）、并行会话协调事项、显式挂账。

## 状态机纪律

- 未有文档不动代码；文档未定稿不写实现；
- 每个实施提交引用其遵循的文档节号；
- 收口时状态推进到「已核销」，验收清单从平文改为勾选清单。
