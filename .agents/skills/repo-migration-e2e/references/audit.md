# 旧实现审计细则

## 四条标准（逐文件过）

1. **正确性**
   - 边界值与空态；错误路径是否真的走到；静默吞错（空 catch、`?? fallback` 掩盖
     应当显式失败的路径）；
   - 并发与竞态：双写、重复触发、晚订阅、分发中退订；
   - 取消路径的全部触发方式（客户端断开、上游中止、超时、停机）。
2. **契约符合**
   - 零跨请求状态（机制层不得持有调用间记忆）；
   - 无策略数据混入机制层（阈值/币种/开关等可变值必须装配注入）；
   - 无隐藏默认（缺省值只住在装配/配置层，且显式声明）。
3. **实现质量**
   - 职责单一（一文件一动词）；无重复（重复处登记提取计划）；热路径预算达标。
4. **依赖方向**
   - 单向：入口 → 应用 → 领域；依赖倒置处用端口；底层不得反向引上层；
   - 基础设施细节（SQL、协议解析）不越层。

## 三个产出清单

- **真 bug 清单（B#）**：编号、位置、级别（资金/数据丢失最优先）、复现条件、
  修复决策（本波修 / 挂账）。每个真 bug 在新实现里配一个回归用例。
- **重复代码清单（D#）**：位置对、提取计划、目标归属层。
- **契约缺口清单**：新旧语义差异点、演进决策（是否破坏、消费方迁移路径）。

## 纪律

- 诚实区分「实测确认」与「待审计」——没看过的文件不许标已审计；
- 可并行委派审计（按模块分片），但裁决必须基于证据回到裁决表；
- 审计发现的旧 bug 要修并说明；**复制的前提是审计无可挑剔**——有问题就升级为
  重构/重写，并把问题带入新实现的测试计划。

## 裁决表（审计完成后填）

| 旧文件 | 裁决                                    | 审计状态             | 动作     |
| ------ | --------------------------------------- | -------------------- | -------- |
| …      | 复制 / 复制+微修 / 重构 / 重写 / 不移植 | 已审计（B#/D# 引用） | 具体步骤 |

「不移植」的行同样保留在表内——迁移文档的显式挂账区需要它（理由 + 后果 + 归属波次）。
