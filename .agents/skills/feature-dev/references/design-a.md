# 模板 A（小功能：单份方案，十几到几十行）

> 适用于小级：纯加法、1-2 个文件、无新外部契约（或契约只是枚举加项）。
> 重量分级的意义：小功能不被仪式感拖死。方案可以只有十几行——但要五节齐全。

```markdown
# <功能名> 方案
> 状态：草稿 | 定稿 | 已实施 | 已核销
> 级别：小

## 契约
- API/接口形态（参数、结果、错误形态；可选参数全部有缺省）
- 副作用与事件（如有）

## 问题域
- 处理：<动词列表>
- 不处理：<每项写清归属哪个消费方>

## 裁决
- <与用户确认过的取舍，标注「用户裁决」；默认裁决给否决窗口>

## 测试口径
- 契约断言、边界清单（先列再实现）

## 验收清单
- [ ] 外部契约逐条
- [ ] 边界/异常清单逐条
- [ ] 四门 + 覆盖率数字如实报告
```

小级专属纪律：

- **替代落点**：方案可由提交/PR 正文或函数头注释块承载，同样满足可追溯
  （不必为几十行的改动单开文档文件）；落库随实现同一提交；
- **最轻达成**：展示方案与默认裁决 → 用户一句确认或否决窗口内推进，
  允许单轮「方案+实现」连续完成（SKILL.md §0）；
- 升级信号：实现中发现跨层/契约变形/并发语义，即停——升级到模板 B
  （`design-b.md`）补齐缺口再继续。
