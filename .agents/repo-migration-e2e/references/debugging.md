# 集成缺陷定位纪律（e2e/集成测试挂起或抓到缺陷时）

## 心法

e2e 挂了是资产：接缝缺陷只有它够得到。目标不是「让它绿」，而是**把挂起变成
一个可命名、可微复现的根因**，修掉后在迁移文档登记。

## 流程

### 1. 先确认证据，再动手

- 挂起点在哪个 await / 哪一层？超时前有没有部分输出（响应头到了吗？上游收到
  请求了吗？账单落库了吗？）；
- 用打点代理（请求进/出全程可见的中间层）确认「请求是否发出被测服务、数据是否回流」
  ——区分「没发出去」和「发了没人读」；
- **无报错超时的首选取证是挂起瞬间的调用栈转储**（解释器自带的栈打印/信号触发
  dump，附在超时回调里触发亦可）——比加打点重跑更快定位卡点；
- **单跑 vs 全量跑对比**：两者结果不一致本身就是证据（并发/顺序依赖、连接池、
  共享缓存键污染）；
- 缩短反馈环合法且推荐：单跑该用例、复现时临时收紧超时旋钮。**边界**：只影响
  本次定位运行、不进提交的旋钮收紧合法；门禁超时/覆盖率阈值调低换绿永远禁止。

### 2. 逐层二分

HTTP 入口 → 应用编排 → 能力包 → 依赖库，每层写一个最小直调用例（绕过上层
直调下层）。哪层从「正常」变「挂起」，界就在哪。

### 3. 微复现优先于源码阅读

怀疑平台/运行时语义时，写 10-30 行、不 import 任何业务代码的裸运行时脚本
验证组合本身。**多运行时交叉验证**（不同版本的解释器跑同一脚本）能区分
「平台一致语义（我们用错了）」与「特定版本回归（升级/绕开）」。

注意：微复现本身也要写对——例如验证流管道时，若没有人消费输出端，
`await pipeTo` 因背压不完成是**正确行为**，不是缺陷。先排除测试自身的误解。

### 4. 高频坑清单（真实踩过，逐项核查）

- **流式需求耦合自锁**：变换流的 transform 回调可能只在下游有人读时才执行。
  「等首个事件再返回流给调用方」的结构会互等成死锁——表面症状是客户端永远
  拿不到响应头。修法方向：上游首字节已被预读确认时，事件可即刻合成发出；
  一次性事件在事件总线里做幂等缓冲 + 晚订阅重放。
- **tee 分支取消语义**：流分叉后取消单个分支可能长期不 resolve（要等两分支
  齐 cancel），且挂起时另一分支的管道搬运停摆。修法方向：预读用原始 reader
  直读 + 「先回放缓存块再续读」的包装流，零分叉。
- **连接池耗尽**：并发负载下随机 5xx、错误码为连接超时——对齐测试装置与
  旧口径的池上限，而不是调小并发。
- **模块解析条件**：development/production 条件改变依赖目标（源码 vs 构建产物），
  子进程与测试宿主行为不同先查这个；产物缺静态资产（JSON 等）会让产物形态
  一定失败——构建脚本补资产拷贝。
- **背压与缓冲语义**：按需拉取的转发链路里，中间层只累计「已交付 + 预读」，
  断言口径要跟着「实际交付内容」走。
- **打包/格式化工具交互**：临时插桩被格式化器折行导致清理残留——按标记字符串
  删，删完全文 grep 验证零残留。

### 5. 修复与回归

- 修复落点可能在「别人的包」——仍然修（发现即修并说明），但注意并行开发
  边界：改最小面、不重排他人文件、提交时只点名自己的路径；
- 修复所在包的**全部既有测试**回归一遍；e2e 里为该缺陷补一条能反复暴露它的
  用例（它当初怎么挂的，就让用例怎么站着）；
- 迁移文档登记：缺陷编号、症状、根因（平台语义还是组合错误）、修法、回归结果。
