# 测试标准与写法纪律

## 必测清单（按改动类型强制）

1. **契约级**：公共契约用测试锁死——
   - 机制位与文档词表逐项相等（导出枚举 == 文档词表，双向封闭）；
   - 判别联合穷举（每种形态至少一条断言）；
   - 事件时序：终态保证最后、一次性事件恰好一次；
   - 契约变了测试必须同步变，不允许契约与测试漂移。
2. **bug 回归**：开发中发现的每个 bug 一个回归用例；用例名注明症状
   （修复没有回归用例 = 没修完）。
3. **边界与异常（不可省）**：
   - 零值/空/垃圾形状不抛不崩；超大与超长输入；截断与部分形态；
   - 取消路径的全部触发方式；超时矩阵（边界两侧各一条）；
   - 竞态：并发交错、分发中退订、晚订阅重放。
4. **表驱动**：错误码表、参数矩阵、方言差异用数据表 + 遍历断言——
   新增表项自动获得覆盖，不逐项手写用例。
5. **隔离/权限面（涉及时强制）**：越权矩阵是安全回归项——主体 × 资源 ×
   操作全维遍历，断言跨边界不可见（不只是 403/404——列表、详情、更新、
   删除、导出、聚合报表每条读路径都要过）；越权是安全缺陷，不算普通 bug。

## 写法纪律

- **断言前先读口径**：模块文档/注释写的计量口径（含不含缓存、取整方向、
  累积分段）与断言冲突时，先裁决改文档还是改代码，**不许硬改断言凑绿**；
- 透传/字节保真类用逐字节对照，不用语义概括（「包含某词」≠ 透传验证）；
- 计时器类用例短时限 + 容差；异步取消链允许传播等待；
- **禁止凑覆盖率的空转用例**：每个断言必须存在一个能让它失败的历史或理由
  ——写不出失败理由的用例是噪音，删掉。

## 覆盖率

- 阈值写进测试运行器的 coverage 配置（行/语句/函数 ≥ 90、分支 ≥ 85 是常用起点，
  以项目现状定但只升不降）；
- 未达标保持红：只补测试，不调阈值；
- 汇报时如实报告数字——「门禁全绿」不等于「覆盖率达标」，两个都要说。

## e2e 旅程补充（跨进程功能）

- 优先复用既有装置：种子事实走装置口径（新事实显式种子，断言值与契约一致）；
  替身脚本缺的向量按需扩；旅程断言验证**业务终态**（对账/状态一致性/幂等），
  不只是状态码；
- 新旅程挂进装置的运行入口；真凭证/花钱场景进 opt-in real 门；
- 装置自身也要可信：测试间无共享可变状态、数据自清、文件级串行（共享缓存键时）；
- e2e 挂起/失败 ≠ 收拾掉它，按 debugging 纪律定位到底（见 debugging.md）。

## 新功能回归面

- 改动触及存量模块时：该模块既有测试全量回归一遍（不是只跑新增的）；
- 发现存量缺陷：当场修 + 回归用例 + 提交说明；大缺陷登记挂账再决策。
